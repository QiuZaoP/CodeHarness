# 变更审阅、应用与任务报告

## 最终 Diff

Harness 接受 `COMPLETE` 前创建不可变 `FINAL` 快照，并通过临时 Git index 生成包含新增、修改
和删除文件的结构化 Diff。重命名在首期拆分为删除和新增，避免公共 `FileChange` 缺少旧路径
时产生不可安全应用的记录。

每条 `FileChange` 保存：

- 文件状态、增删行数和完整补丁；
- `PENDING / ACCEPTED / REJECTED` 审阅决定及乐观版本；
- 产生该变更的 `toolCallId` 和 `stepId`。

无法追溯到已完成副作用工具的工作区修改会阻止任务进入审阅态。相同 Diff 重新汇总时保留
原 ID、决定和版本；补丁变化时重新进入 `PENDING`。

## 审阅事务

文件决定更新使用 `changeId + expectedVersion` 乐观锁。决定、版本、`change.updated` 事件和
`file_change` 审计位于同一 SQLite 事务。任务不在 `READY_FOR_REVIEW` 时不能修改决定。

首期支持文件级接受或拒绝。区块级审批需要先扩展补丁片段标识和应用语义，不能把部分补丁
伪装成整个文件已接受。

## 安全应用

`apply` 要求所有变更都已审阅，并在写入源目录前重新生成任务工作区 Diff，与持久化审阅
版本逐字段比较。仅 `ACCEPTED` 文件会应用：

- 新增文件要求源路径和任务基线中都不存在；
- 修改、删除要求源文件内容仍与任务基线一致；
- 所有路径拒绝绝对路径、越界和符号链接；
- 写入使用同目录临时文件和原子替换；
- 多文件应用先备份全部目标，任一步或数据库状态提交失败都会补偿恢复。

`REJECTED` 文件保留在任务工作区和审阅记录中，但不会写入源目录。成功后任务进入
`APPLIED`，事件中的 `changeCount` 是实际接受文件数。

## 报告

任务报告由持久事实生成，包含状态、计划、文件变更、验证结果、工具与步骤关联以及风险。
存在待审阅文件、没有验证、最近验证失败或任务停止原因时会产生风险项。报告 API 在完整
API 接入阶段发布。
